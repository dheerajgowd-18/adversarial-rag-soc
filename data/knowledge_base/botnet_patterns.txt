TITLE: Botnet C2 Communication Patterns and Detection

## Overview
A botnet is a network of compromised machines (bots) controlled by an attacker
via Command-and-Control (C2) infrastructure. Detection focuses on C2 communication
patterns — the periodic "check-in" traffic from infected hosts.

## C2 Communication Models

### HTTP/HTTPS C2 (Most Common, Hardest to Detect)
- Bot makes regular HTTP requests to attacker-controlled server
- Traffic looks identical to normal web browsing
- Detection relies on behavioral anomalies: timing regularity, rare domains

### IRC-Based C2 (Legacy)
- Bot connects to IRC server channel, receives commands
- Port: 6667 (IRC) or non-standard ports
- Very regular connection intervals

### DNS-Based C2
- Commands encoded in DNS query/response
- Extremely hard to detect — DNS is rarely blocked
- High volume of unique DNS lookups to rare domains

### Peer-to-Peer C2 (Decentralized)
- Bots communicate with each other, no single C2 server
- Traffic pattern: many small flows to many different IPs
- Very difficult to detect without global view

## Botnet Beaconing Signature (Key Detection Method)

Beaconing = bot periodically checks in with C2 server.
This creates a distinctive TIMING signature:

  Regular intervals: bot contacts C2 every N seconds (N=60, 300, 3600)
  Small payload: each check-in is tiny (heartbeat, not data transfer)
  Consistent destination: same IP:port every check-in
  Low throughput: just enough to maintain C2 channel

CICIDS2017 Botnet Statistical Profile:
  flow_duration_us:    median 1,024,663 (1 second — short but not ultra-short)
  fwd_packets:         median 3
  bwd_packets:         median 3
  total_bytes:         median 18 bytes           ← VERY distinctive
  packet_length_mean:  median 2.57 bytes         ← near-zero payload
  flow_bytes_per_sec:  median 17.6 B/s           ← extremely slow

CRITICAL INDICATOR: Long-lived flow (>100,000us) with total_bytes < 50.
A 1-second connection that exchanges only 18 bytes is a C2 heartbeat.
No legitimate application maintains connections this long with this little data.

## Distinguishing Botnet from Legitimate Traffic

Tiny packets in legitimate traffic:
  - TCP keepalive: 0 bytes payload, but ONLY after long idle period in established connection
  - DNS: small but very short duration (< 1ms)
  - NTP: small but very regular and only to known NTP servers

Botnet beaconing:
  - Sustained flow duration (0.5–60 seconds typical)
  - Payload: < 50 bytes TOTAL for the entire conversation
  - Periodic recurrence at fixed intervals (jitter ±10%)
  - Destination: IP without legitimate hostname, or fast-flux domain

## Indicators of Compromise (IoC)

Network IoCs:
  - Connections to newly registered domains (< 30 days old)
  - Connections to IPs with no associated hostname (bare IP HTTP)
  - Regular beaconing pattern: same dst_ip:port every N minutes
  - Encrypted traffic to non-CDN IPs on port 443
  - HTTP User-Agent strings that don't match browser fingerprints

Host IoCs:
  - Scheduled tasks or cron jobs running every N minutes
  - Process making network connections with no UI
  - Unusual outbound connections from server processes

## Triage Guidance

Classify as BOTNET C2 (SUSPICIOUS) if:
  - Flow duration > 100,000us AND total_bytes < 50 AND fwd_packets < 10
  - Same source-destination pair appears repeatedly at regular intervals
  - packet_length_mean < 5 bytes in a flow lasting > 0.5 seconds

Immediately escalate if:
  - Source is a production server (servers don't beacon to random IPs)
  - C2 destination appears in threat intelligence feeds
  - Multiple internal hosts beaconing to same C2 destination

## Severity Assessment
  Severity: CRITICAL
  Impact: System compromise, potential for lateral movement, data exfiltration
  Recommended action: Isolate host, forensic investigation, check for persistence
